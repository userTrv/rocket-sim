# Правила для работы в репозитории

## Зависимости

- Ставить только версии, опубликованные не меньше 7 дней назад. pnpm это проверяет сам (`minimumReleaseAge` в `pnpm-workspace.yaml`), для остального (npm-пакеты вне pnpm, GitHub Actions, Docker-образы, бинарники) смотреть дату релиза вручную.
- Только известные пакеты из официального реестра: с историей, живым репозиторием и заметным числом скачиваний. Перед добавлением нового пакета проверять точное имя (тайпсквоттинг), автора и нужен ли он вообще. Без git- и URL-зависимостей.
- Настройки защиты в `pnpm-workspace.yaml` не ослаблять и не обходить (`--config.minimum-release-age=0`, `approve-builds`, `onlyBuiltDependencies` и т. п.) без явного согласия владельца.
- Установка в CI и при проверках — `pnpm install --frozen-lockfile`. `pnpm-lock.yaml` меняется только вместе с `package.json` и попадает в тот же коммит.
- Версия pnpm закреплена в `packageManager` в `package.json` вместе с хешем.
- GitHub Actions подключать по полному SHA коммита с комментарием-тегом (`uses: owner/action@<sha> # vX.Y.Z`), только от известных авторов.

## Секреты и доступы

- Никаких ключей, токенов и паролей в коде, коммитах, логах, PR и комментариях. Секреты CI — только в GitHub Secrets, адреса и прочее несекретное — в Variables.
- `.env*`, `*.pem`, `*.key` в `.gitignore`; перед коммитом смотреть `git diff --cached` на предмет случайно попавших секретов.
- Не выводить секреты в консоль (`echo`, `set -x`, `env`, `cat` ключа), не передавать их аргументами командной строки, не отправлять во внешние сервисы.
- В workflow права по минимуму (`permissions: contents: read`, дописывать только нужное), `persist-credentials: false` у checkout, временные ключи удалять в шаге с `if: always()`.
- Нашёлся утёкший секрет — сразу сообщить владельцу: его надо отозвать и перевыпустить, одного удаления из истории мало.
